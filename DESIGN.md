## 1. Цель и границы

**Цель.** Одна среда на карте, которая запускает игры на LÖVE 11.x на Miyoo Mini / Mini Plus под
OnionOS без порта под каждую игру; для игр, которым этого мало, — небольшой профиль игры вместо
порта. Игры ставятся через Port Store.

**Входит:**
- запуск `.love` и «склеенных» `.exe` Windows-версий (LÖVE с приписанным zip);
- весь `love.graphics` LÖVE 11.5, отрисованный процессором; окно, ввод (клавиши и геймпад),
  звук, сохранения;
- подгонка экрана под разные разрешения игр;
- профили игр, отчёт совместимости, список совместимости;
- пакет для Port Store и рецепты игр.

**Не входит (сейчас):**
- общий исполнитель GLSL: шейдеры — по стратегии раздела 4.3;
- 3D (`love.graphics` 3D-режимы, `Mesh` с глубиной), `love.video` (Theora) — позже, если
  понадобится;
- LÖVE 12; LÖVE 0.9 и старше — после 0.10 (этап 7);
- мышь как основное управление (только виртуальный курсор по профилю).

**Устройства.** Mini Plus (Wi-Fi не нужен), Mini, Mini v4 и Flip (752×560) — те же сборки, свои
масштабы экрана.

## 2. Устройство в целом

```
 run.sh <игра>
   │  CPU-частота, LD_LIBRARY_PATH, LD_PRELOAD=libdspfix.so:libpadsp.so, XDG_DATA_HOME
   ▼
 love (LÖVE 11.5, одна правка в boot.lua)  ── игра: games/<id>/game.love | Game.exe
   │  boot.lua: до conf.lua игры → require "lovemini.boot"
   ▼
 lovemini/ (Lua, LuaJIT FFI)
   boot.lua      настройки conf (окно и графика LÖVE выключены), профиль игры, подмены модулей
   graphics.lua  love.graphics поверх libmini2d
   window.lua    love.window: размер игры ↔ экран, режимы масштаба
   input.lua     кнопки Mini → love.keyboard, виртуальный геймпад love.joystick, выход
   shaders.lua   узнавание шейдеров и процессорные замены
   compat.lua    совместимость версий LÖVE, отчёт о недостающих вызовах
   ▼
 libmini2d.so (C)                     поверхности, растеризация, NEON, работа для 2-го ядра
   present-поток ── MI_GFX: масштаб, поворот 180°, на экран (страницы fb0)
   evdev ── очередь кнопок для input.lua
 OpenAL Soft (родной love.audio) → OSS → libdspfix → libpadsp → audioserver OnionOS
```

Что остаётся родным LÖVE: `love.audio`, `love.sound`, `love.filesystem` (PhysFS), `love.image`
(разбор PNG/JPG в `ImageData`), `love.font` (FreeType: растр глифов), `love.math`, `love.physics`
(Box2D), `love.thread`, `love.timer`, `love.event`, `love.system`, `love.data`. Подменяются:
`love.graphics`, `love.window`, ввод (`love.keyboard`, `love.joystick`, `love.mouse`).

### 2.1. Как среда встаёт перед игрой

У LÖVE свой скрипт старта (`src/scripts/boot.lua`, вкомпилирован в программу). Одна правка при
сборке LÖVE: после разбора аргументов и до `conf.lua` игры —

- `package.path` дополняется папкой `lovemini/` (путь из переменной `LOVEMINI_DIR`);
- `require("lovemini.boot")`: он оборачивает `love.conf` игры: после её настроек выставляет
  `t.window = false` (LÖVE не создаёт окно и контекст OpenGL), `t.modules.graphics = false`,
  оставляя остальное как просила игра; запоминает `t.window.width/height` игры — это её
  логический размер (по умолчанию LÖVE — 800×600);
- после загрузки модулей LÖVE ставит свои `love.graphics`, `love.window`, `love.mouse`,
  дополняет `love.keyboard` и `love.joystick`, запускает `libmini2d`.

Обычный `love.run` LÖVE работает без изменений: он вызывает `love.graphics.isActive`, `origin`,
`clear`, `love.draw`, `present` — их даёт наш модуль. Если игра пишет свой `love.run`, всё то же.

Порт Panel Attack делает подмену изнутри папки игры; правка `boot.lua` нужна, чтобы игру не
трогать.

## 3. libmini2d (C)

Основа — `mini2d.c` из порта Panel Attack (MIT, snyderman3000); форк с указанием авторства
(раздел 12).

### 3.1. Поверхности

- `m2d_surf`: `px` (ARGB8888, альфа заранее умножена), `w`, `h`, `stride`; у заднего буфера —
  физический адрес (память MMA, для MI_GFX).
- **Таблицы участков** (уже есть): для статичных картинок по строкам — тройки
  `{x0, x1, непрозрачно}`; прозрачное пропускается, непрозрачное копируется без смешивания.
- **Вид** (`surface_view`): прямоугольник внутри другой поверхности без копии (атлас,
  `Quad`).
- **Новое: палитровые поверхности** (`m2d_surf8`: индексы 8 бит + палитра 256 ARGB) для больших
  наборов тайлов: в 4 раза меньше памяти, блит с подстановкой палитры.
- **Новое: кэш масштаба**: поверхность, пересэмплированная под частый размер показа
  (уже есть `surface_resample`, добавить учёт памяти и вытеснение по LRU).

### 3.2. Операции

| Операция | Есть | Сделать |
|---|---|---|
| `clear`, `fill` (прямоугольник) | да | — |
| `blit`: часть поверхности → прямоугольник, масштаб, отражение, оттенок, режим смешивания | да | NEON для масштаба и оттенка; работа для 2-го ядра |
| `line` с толщиной | да (оси, прямые) | наклонные линии с толщиной (как четырёхугольник), стыки (`setLineJoin`) |
| `circle`, кольцо | да | `ellipse`, `arc` (pie / open / closed) через многоугольник |
| **аффинный блит** (поворот, наклон) | нет | обратное отображение по строкам, nearest и (по желанию) bilinear |
| **многоугольник** (заливка) | нет | заливка по строкам (scanline, even-odd / nonzero), выпуклые — быстрый путь |
| **треугольники с текстурой** | нет | для `Mesh` и `ParticleSystem`: аффинная текстура на треугольник, цвет вершин |
| **трафарет** | только прямоугольник (как обрезка) | 8-битный буфер трафарета: запись (`stencil`), проверка (`setStencilTest`) |
| обрезка (`setScissor`) | да | — |
| маска каналов (`setColorMask`) | нет | маска при записи пикселя (редко нужна — простой путь) |

**Режимы смешивания** (альфа заранее умножена, `s` — источник, `d` — приёмник, `sa` — альфа
источника):

| LÖVE | Формула |
|---|---|
| `alpha` | `d = s + d·(1 − sa)` |
| `add` | `d = d + s` (насыщение) |
| `subtract` | `d = d − s` (насыщение) |
| `multiply` | `d = s·d + d·(1 − sa)` |
| `screen` | `d = s + d·(1 − s)` |
| `lighten` / `darken` | `max` / `min` по каналам |
| `replace` | `d = s` |

Режим `alphamultiply` у LÖVE (цвет не умножен) пересчитывается в умноженный при `setColor` и
загрузке картинок; `premultiplied` — как есть.

### 3.3. Скорость

- **NEON**: горячие циклы — блит 1:1 с альфой, масштабный блит, оттенок, заливка, палитровый
  блит. Обычная версия на C остаётся как эталон для тестов.
- **Второе ядро**: очередь работ `m2d_job` с постоянным вторым потоком (не создавать потоки
  на кадр); крупная отрисовка (больше N тысяч пикселей) делится по строкам: половина — здесь,
  половина — там. Мелкие — на месте.
- **Показ** (уже есть): кадр готов → поток показа отдаёт его MI_GFX (масштаб, поворот, вывод
  в невидимую страницу, переключение); игра в это время рисует следующий в другой буфер.
- Статистика: время растеризации, показа, число вызовов — для `getStats` и лога.

### 3.4. Ввод и выход

`m2d_poll_key` (evdev, уже есть) → очередь (код, нажато/отпущено). Режим host: нажатия из файла
сценария.

### 3.5. Режим host

`libmini2d_host.so` (уже есть в основе): задний буфер в обычной памяти, кадры — в PNG (добавить,
сейчас PPM), без MI_GFX и evdev. На нём — все тесты на ПК (раздел 7).

## 4. Lua-часть (`lovemini/`)

### 4.1. `graphics.lua`: модель

- **Состояние**: преобразование — аффинная матрица 2×3 и стек (`push`/`pop` с вариантом
  `"all"` для всего состояния), цвет (уже умноженный), цвет фона, режим смешивания, холст-цель,
  обрезка, трафарет (режим и значение), шрифт, толщина и стиль линий, размер точек, «шейдер».
- **Текстура** (`Image`, `Canvas`): логический размер (что видит игра) и поверхность хранения в
  масштабе `storage_scale` (как `RENDER_SCALE` в порте: игра рисует в 1280×720, хранится
  640×360). По умолчанию `storage_scale` = масштаб экрана (раздел 4.4): картинки хранятся уже в
  размере показа, почти все блиты 1:1.
- **Выбор пути отрисовки** `draw(tex, quad, x, y, r, sx, sy, ox, oy, kx, ky)` с текущей
  матрицей:
  1. без поворота и наклона, масштаб = масштабу хранения → блит 1:1 (с таблицами участков);
  2. без поворота, другой масштаб → масштабный блит (или кэш масштаба, если повторяется);
  3. поворот или наклон → аффинный блит;
  4. с «шейдером», для которого есть замена → тот же путь с эффектом (раздел 4.3).
- **SpriteBatch**: массив четвёрок (quad, матрица, цвет) в памяти FFI, рисуется одним вызовом C
  (без вызова Lua на спрайт).
- **Текст**: `love.font.newRasterizer` (родной FreeType LÖVE) → глифы в страницы атласа
  (поверхности 256×256), кэш на шрифт; `print`/`printf` с переносом, выравниванием, цветными
  частями; `Text` — заранее разложенный текст; `newImageFont` — глифы из картинки.
- **Холсты**: поверхности; `setCanvas` с вложенностью и списком (MRT — только первый);
  `newImageData` / `captureScreenshot` — чтение поверхности в `ImageData` (родной `love.image`).
- **Mesh**: вершины в памяти FFI (позиция, uv, цвет), режимы `fan`, `strip`, `triangles`,
  карта вершин; рисуется треугольниками с текстурой.
- **ParticleSystem**: своя реализация на Lua поверх массива частиц (формулы LÖVE: скорость,
  ускорение, радиальное и касательное ускорение, вращение, цвета и размеры по времени жизни,
  излучение), отрисовка — как SpriteBatch.
- **getStats** — из статистики libmini2d; `getSupported`, `getSystemLimits`,
  `getRendererInfo` — честные значения («mini2d», без шейдеров).

### 4.3. Шейдеры (`shaders.lua`)

`newShader(code)` возвращает объект, который хранит текст, нормализованный хэш (без
комментариев и пробелов), полученные значения (`send`, `sendColor`) и найденную замену.

1. **Каталог замен** (общий для всех игр): типовые шейдеры, узнаваемые по хэшу или по
   простым признакам текста:
   - `flash` — заливка цветом с альфой спрайта (`return vec4(c.rgb, tex.a)`);
   - `grayscale`, `tint` (умножение на цвет), `colorize`, `invert`;
   - `palette_swap` — подстановка по таблице цветов;
   - `alpha_mask`, `dissolve` по порогу шума.
   Каждая замена — режим блита в C с параметрами из полученных значений (`m2d_effect`).
2. **Профиль игры**: таблица `shaders = { [hash] = "flash" | function(params) … end }` — свои
   замены, в том числе на Lua через `ImageData`-проход для редких.
3. **Полноэкранные эффекты** (CRT, bloom, свечение, виньетка), распознанные по признакам
   (рисование холста размером с экран с шейдером): по умолчанию выключены.
4. **Неизвестный шейдер**: рисовать без него; в отчёт — хэш, первые строки, где создан
   (стек Lua), сколько раз использован. Это материал для каталога и профилей.

### 4.4. Экран (`window.lua`)

- Игра получает свой логический размер: `love.graphics.getDimensions`, `love.window.getMode`
  возвращают размер из её `conf.lua` (или `setMode`).
- **Режимы масштаба** (профиль, по умолчанию `fit`):
  - `fit` — вписать с полями, масштаб `min(640/w, 480/h)` (800×600 → ровно 0,8, без полей);
  - `fill` — заполнить с обрезкой (16:9 → обрезка по бокам, как Panel Attack);
  - `integer` — целый масштаб вниз (пиксельные игры 320×240 → ×2);
  - `stretch` — растянуть.
- Масштаб применяется **как начальное преобразование** каждого кадра (рисование сразу в
  разрешении экрана), а не через холст размером с игру с последующим уменьшением: так нет
  лишнего прохода по большим кадрам. Холст размером с игру — только по профилю (игры, которые
  читают пиксели экрана).
- Координаты мыши (виртуальный курсор) переводятся обратно в логические.
- Mini v4 / Flip: экран 752×560, файл `full_resolution` рядом с запускателем (как у Port Store).

### 4.5. Ввод (`input.lua`)

Кнопки Mini (коды evdev, как в Port Store):

| Кнопка | Клавиша LÖVE по умолчанию | Кнопка геймпада |
|---|---|---|
| D-pad | `up`, `down`, `left`, `right` | `dpup`… |
| A | `space` (часто «действие») | `a` |
| B | `lctrl` | `b` |
| X | `lshift` | `x` |
| Y | `lalt` | `y` |
| L1 / R1 | `e` / `t` | `leftshoulder` / `rightshoulder` |
| L2 / R2 | `tab` / `backspace` | оси `triggerleft` / `triggerright` (1.0) |
| Select | `rctrl` | `back` |
| Start | `return` | `start` |
| Menu | `escape` | `guide` |

- Клавиши: по умолчанию — **как отдаёт SDL на Mini** (Space, LCtrl, LShift, LAlt, E, T, Tab,
  Backspace, RCtrl, Enter, Esc), чтобы совпадать с другими портами; профиль задаёт свою
  раскладку (`keys = { a = "z", b = "x", … }`): у многих игр на ПК «действие» — `z`/`x`/`space`.
- **Виртуальный геймпад**: `love.joystick.getJoysticks()` возвращает один объект («Miyoo Mini»,
  `isGamepad() == true`), события `joystickadded` при старте, `gamepadpressed/released`,
  `isGamepadDown`, `getGamepadAxis`. Игры с поддержкой геймпада управляются без профиля.
- Нажатие отдаётся **и** клавишей, **и** кнопкой геймпада (игры, слушающие оба, получат оба —
  в профиле можно выключить одно).
- `love.keyboard.isDown`, `isScancodeDown`, `setKeyRepeat` (повтор — свой).
- **Выход**: Select + Start (держать) → `love.event.quit()`; Menu — по умолчанию клавиша
  `escape` (меню игры), keymon OnionOS свои сочетания обрабатывает сам.
- **Текст** (`love.textinput`, `love.keyboard.setTextInput`): экранная клавиатура в окне
  (этап 4+).
- **Виртуальный курсор** (профиль `mouse = true`): D-pad двигает, A — левая кнопка, B — правая;
  `love.mouse.getPosition`, `isDown`, события `mousepressed/released/moved`.

### 4.6. Звук

- Родной `love.audio` (OpenAL Soft 1.21, отдельной библиотекой) → OSS `/dev/dsp` → `libdspfix`
  (перехват `open64`, из порта Panel Attack) → `libpadsp` OnionOS → audioserver.
- `alsoft.conf`: частота и размер буфера под Mini (как в порте).
- **Потоковая подмена**: `love.audio.newSource(path, "static")` для файла больше порога (профиль,
  по умолчанию 1 МБ) становится `"stream"`: длинная музыка не разжимается в память.
- Подготовка звука (необязательная, по профилю, при первом запуске или в сборке рецепта): моно
  и 22 кГц для тяжёлых игр (как Gravity Circuit).

### 4.7. Файлы и сохранения

- Игра запускается как `love games/<id>/game.love` (или `Game.exe`: PhysFS находит zip в конце
  файла).
- Папка сохранений LÖVE (`love.filesystem.getSaveDirectory`) — через `XDG_DATA_HOME` в
  `Saves/CurrentProfile/saves/love-mini/` (место сохранений OnionOS, переживает обновления
  среды и игры).
- Большие игры, которые распаковывают ресурсы, — в папку игры, не в память.

### 4.8. Профиль игры (`games/<id>/profile.lua`)

```lua
return {
  love = "11.5",                 -- версия, под которую игра (слой совместимости)
  screen = "fit",                -- fit | fill | integer | stretch
  storage_scale = nil,           -- масштаб хранения картинок (nil: = масштаб экрана)
  canvas_screen = false,         -- рисовать через холст размером с игру
  keys = { a = "z", b = "x" },   -- своя раскладка клавиш
  gamepad = true, keyboard = true,
  mouse = false,                 -- виртуальный курсор
  cpu_mhz = 1500,                -- частота на время игры (возврат при выходе)
  shaders = { ["a1b2c3"] = "flash" },
  stream_over_kb = 1024,
  patches = function(love) end,  -- последняя возможность: правки после загрузки игры
  notes = "…",
}
```

Профиль ищется рядом с игрой, затем в общем каталоге профилей пакета (по имени и хэшу файла
игры). Без профиля — значения по умолчанию.

### 4.9. Совместимость версий (`compat.lua`)

- Версия игры — из `t.version` в её `conf.lua` (или профиля).
- **0.10** (этап 7): цвета 0–255 → 0–1 во всех функциях цвета; старые имена
  (`love.graphics.setColor` с таблицей, `Image:getData`, `love.filesystem.exists` и т.п.),
  изменившиеся обратные вызовы — тонкий слой переименований и пересчётов перед игрой.
- 0.9 — после 0.10, если будет спрос.

### 4.10. Отчёт совместимости

Режим `LOVEMINI_REPORT=1` (на ПК, на libmini2d host):

- каждая функция `love.*` и методы объектов обёрнуты счётчиком; заглушки и неподдержанные
  параметры (поворот там, где его нет, режимы смешивания, шейдеры) записываются с местом вызова;
- сценарий нажатий (файл), N кадров, кадры в PNG каждые K;
- итог — `report.json`: какие функции вызывались, что не поддержано, неизвестные шейдеры, ошибки
  Lua, время кадра на ПК, пиковая память Lua и текстур.

Из отчётов собирается список совместимости (раздел 10).

## 5. Пакет на карте и запуск

```
Roms/PORTS/Games/love-mini/
  bin/love                  LÖVE 11.5 (правленый boot.lua)
  lib/                      libluajit, libSDL2 (Steward-Fu), libopenal.so.1, libfreetype, libpng,
                            libz, libogg, libvorbis*, libtheora, libmodplug, libmini2d, libdspfix
  lovemini/                 Lua-часть (раздел 4)
  profiles/                 общий каталог профилей
  alsoft.conf
  run.sh                    run.sh <id>
  games/<id>/game.love      или Game.exe (свой файл пользователя)
  games/<id>/profile.lua    необязательно
```

`run.sh <id>`:
1. папка пакета, `LD_LIBRARY_PATH=lib`, `LD_PRELOAD="lib/libdspfix.so /mnt/SDCARD/miyoo/lib/libpadsp.so"`
   (если работает audioserver), `ALSOFT_CONF`, `LOVEMINI_DIR`, `XDG_DATA_HOME`;
2. частота процессора из профиля — средством OnionOS (как делает порт Balatro), возврат при
   выходе и по сигналу;
3. `exec bin/love games/<id>/game.love` (или `.exe`), лог в `games/<id>/log.txt`.

Запускатель игры в списке — ярлык Ports (`Roms/PORTS/Shortcuts/<Жанр>/<Игра>.port`) или
запускатель MiyooPorts от Port Store: оба вызывают `run.sh <id>`.

## 6. Свой репозиторий игр (`love-mini-games`)

Каталог игр для love-mini — отдельный репозиторий: профили, рецепты, список совместимости и
сборка пакетов игр. Он же — место, куда сообщество приносит игры.

### 6.1. Устройство

```
love-mini-games/
  games/<id>/
    game.json         описание игры (ниже)
    profile.lua       профиль love-mini (раздел 4.8), если нужен
    cover.png         картинка (своя или с разрешения автора)
    shortcut/         при надобности: свой ярлык, иконка
  tools/build.py      сборка: игры → пакеты и manifest.json
  .github/workflows/  каждый день и на изменения: собрать, проверить, опубликовать
  COMPATIBILITY.md    список совместимости (собирается из game.json)
```

`game.json`:

```json
{
  "id": "some-jam-game",
  "name": "Some Jam Game",
  "love": "11.5",
  "license": "MIT",
  "source": { "github": "owner/repo", "asset": "\.love$" },
  "redistribute": true,
  "status": "playable",
  "fps": { "mini-plus": 30 },
  "devices": ["mini-plus"],
  "categories": ["action"],
  "notes": "…"
}
```

`source` — откуда взять игру:
- `github` + `asset` — выпуск автора на GitHub (как в рецептах Port Store);
- `url` + `sha256` — прямой адрес у автора (свой сайт);
- `bundled` — `.love` лежит в этом репозитории: **только если лицензия игры разрешает
  распространение** (`redistribute: true` и `license` указаны, текст лицензии рядом);
- `owned` — коммерческая игра: файл приносит пользователь (`needs`: что и куда, как в Port
  Store); в репозитории — только профиль.

### 6.2. Что публикуется

Сборка в GitHub Actions на каждую игру делает **zip, разложенный от корня карты**:
`Roms/PORTS/Games/love-mini/games/<id>/` (`.love` — если её можно раздавать — и профиль),
ярлык для Ports, картинка. Zip — выпуском репозитория игр; для `owned` и для игр, которые нельзя
раздавать, в zip только профиль и ярлык, а сама игра — от автора или от пользователя.

Плюс **`manifest.json` в формате каталогов авторов Mixtape** (уже читает Port Store,
`recipes/sources/`): по записи на игру — `name`, `version`, `url` zip, `sha256`, `size`,
`categories`, `status`, `assets`, `notes`, `image`, `keep` (сохранения). Добавлено поле
`requires: ["love-mini"]`. Тогда каталог игр подключается к Port Store одним файлом
`recipes/sources/love-mini-games.json`; читать его сможет и Mixtape (без зависимости — тогда
пакет `love-mini` ставится отдельно).

### 6.3. Проверка игр в репозитории

На каждую игру в CI — прогон отчёта совместимости на ПК (раздел 4.10: N кадров по сценарию,
без ошибок, кадры в PNG). Упавшая игра не попадает в выпуск; результат — в `COMPATIBILITY.md`
(статус «проверено на ПК»; «проверено на Mini» ставится вручную по замерам).

## 8. Проверка

| Что | Как | Где |
|---|---|---|
| Растеризатор | тесты C: каждая операция против простой эталонной версии (по пикселю), NEON против обычной | ПК, qemu для ARM |
| `love.graphics` | сцены-примеры на Lua (спрайты, повороты, текст, холсты, трафарет, смешивание, меши, частицы): кадр нашей отрисовки против кадра **настоящего LÖVE на ПК** (OpenGL), допуск по разнице | ПК |
| Игры | отчёт совместимости (4.10) на каждую игру из списка: N кадров по сценарию без ошибок, кадры в PNG | ПК |
| Сборка ARM | запуск под qemu: старт, первые кадры, отчёт | ПК |
| Скорость и память | лог на Mini: время кадра (среднее, 95-й процентиль, худшее), память процесса, кадры на сцену | Mini |

Каждое изменение растеризатора — со сравнением «быстрый путь = эталон» (как в порте Balatro).

## 9. Бюджеты

**Время кадра** (цель — 30 кадров, 33 мс; простые игры — 60):

| Часть | Бюджет при 30 кадрах |
|---|---|
| `love.update` игры (Lua) | ≤ 10 мс |
| `love.draw`: вызовы Lua и подготовка | ≤ 8 мс |
| растеризация (C, два ядра) | ≤ 12 мс |
| показ (MI_GFX, отдельный поток) | параллельно, не входит |

**Память** (128 МБ на всё): OnionOS со службами — замерить (ориентир 30–40 МБ занято);
LÖVE с библиотеками — 15–20 МБ; куча Lua игры; текстуры — по `getStats().texturememory`
с пределом (профиль), сверх — уменьшение масштаба хранения и палитры. Подкачка — только по
выбору пользователя.

## 11. Сборка

- **Тулчейн**: GCC 8.x, glibc 2.28 — наш (`~/.local/opt/miyoomini-toolchain`, как Port Store)
  или `mini_toolchain` Steward-Fu (им собирает snyderman3000; в нём SDL2 и SDK MI_GFX). Решение —
  на этапе 0: SDK MI_GFX и SDL2 Steward-Fu нужны в любом случае.
- **LuaJIT 2.1**: перекрёстная сборка требует 32-битного хост-компилятора (`gcc -m32`, multilib)
  — проверить на нашей ВМ, иначе собирать в контейнере.
- **LÖVE 11.5**: `configure --host=arm-linux-gnueabihf --with-lua=luajit --disable-mpg123`,
  `-mcpu=cortex-a7 -mfpu=neon-vfpv4 -mfloat-abi=hard -D_FILE_OFFSET_BITS=64` (без поддержки
  больших файлов на Mini не читается список папок — замечание из порта); правка `boot.lua`.
- **Зависимости**: из sysroot тулчейна (FreeType, libpng, zlib, Ogg/Vorbis/Theora, ModPlug),
  OpenAL Soft 1.21 — отдельно (LGPL: исходники прикладываются к выпуску).
- Скрипт `build.sh` (воспроизводимо, с версиями), затем — тот же в GitHub Actions (контейнер с
  тулчейном) → zip выпуска.
- Режим host: LÖVE 11.5 для ПК из пакетов системы + `libmini2d_host.so`.
